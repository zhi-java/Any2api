# Admin 管理系统重构 - 企业级现代化面板

## Goal

将当前的 Admin 管理后台重构为企业级现代化面板，提供清晰的渠道管理、直观的数据可视化和优雅的用户体验。

## Current State

### 现有功能（已通过代码分析确认）

**Admin 面板（`/admin`）**：
- 单页 HTML（739 行）
- 暗色主题 UI
- 功能：Token 池状态、会话管理、日志查询、统计信息
- 存在的问题：UI 陈旧、功能堆砌、无渠道区分

**Chat 面板（`/admin/chat`）**：
- 独立的聊天测试页面（734 行）
- 用于测试 API 端点

**后端 API**（`src/routes/admin.js`）：
- `GET /admin/api/stats` - 统计信息
- `GET /admin/api/logs` - 日志查询
- `POST /admin/api/token/add` - Token 管理
- `POST /admin/api/token/login` - 账号登录
- 其他 Token 和指标 API

### 识别的问题

1. **UI 设计陈旧**：
   - 深色主题色彩单调（`#1a1a2e` 背景）
   - 缺少现代化设计元素
   - 没有遵循 design_sense 设计规范

2. **功能混杂**：
   - 所有功能在单一页面中堆砌
   - DeepSeek 和 GLM 渠道数据混在一起
   - 缺少清晰的功能模块划分

3. **渠道管理缺失**：
   - 无法单独管理 DeepSeek 渠道
   - 无法单独管理 GLM 渠道
   - 无渠道切换和对比功能

4. **操作不便**：
   - 缺少快捷操作
   - 实时更新依赖手动刷新
   - 无响应式设计

5. **数据可视化不足**：
   - 统计数据以文本形式展示
   - 缺少图表和趋势分析
   - 无实时监控仪表盘

## Requirements

### 功能性需求

#### 1. Dashboard（仪表盘）模块
- [ ] 总览统计卡片（请求总数、成功率、活跃 Token 数、当前队列）
- [ ] 渠道状态概览（DeepSeek 和 GLM 分别显示）
- [ ] 实时请求趋势图表（最近 1 小时）
- [ ] Token 使用情况环形图
- [ ] 系统运行时间和版本信息

#### 2. DeepSeek 渠道管理模块

- [ ] 账号管理（添加/删除账号）
- [ ] 会话池状态（活跃会话、预热状态）
- [ ] 对话亲和管理（如果启用）
- [ ] 快速操作（强制刷新 Token、清理死亡会话）

#### 3. GLM 渠道管理模块

- [ ] 请求统计（成功率、平均延迟）

#### 4. 日志查询模块
- [ ] 实时日志流（WebSocket 或 SSE）
- [ ] 历史日志查询（按日期、按类型筛选）
- [ ] 聊天日志查询
- [ ] 错误日志高亮
- [ ] 日志导出功能

#### 5. 性能监控模块
- [ ] 请求延迟分布图表（p50, p95, p99）
- [ ] 请求速率时间序列图
- [ ] Token 使用趋势图

#### 6. 系统设置模块（可选）
- [ ] 配置参数展示（只读，来自 .env）
- [ ] 系统维护操作（重启服务、清理缓存）
- [ ] API Key 管理（如果需要多用户）

### 非功能性需求

#### UI/UX 设计
- [ ] **设计风格**：遵循 design_sense（优雅、简洁、专业）
- [ ] **颜色方案**：
  - 背景：柔和 off-white `#F7F5F1`
  - 表面：纯白 `#FFFFFF`
  - 边框：`#E7E3DA`
  - 文字：`#1E2227`
  - 强调色：muted slate-blue `#3C5A78`（hover `#2E4760`）
- [ ] **排版**：
  - 标题：Playfair Display（500-700 weight）
  - 正文：Inter（400-500 weight）
- [ ] **布局**：
  - 侧边栏导航（固定，约 240px 宽）
  - 主内容区（响应式）
  - 顶部工具栏（面包屑、用户信息、快捷操作）
- [ ] **响应式**：支持桌面（1920px+）、笔记本（1366px+）、平板（768px+）

#### 技术要求
- [ ] 纯 HTML/CSS/JS（无需构建工具，保持简单）
- [ ] 使用现代 ES6+ 特性
- [ ] 图表库：Chart.js 或 lightweight 替代（CDN）
- [ ] 实时更新：Server-Sent Events（SSE）或轮询
- [ ] 向后兼容现有 API

#### 性能要求
- [ ] 首屏加载 < 2 秒
- [ ] 页面切换流畅（< 100ms）
- [ ] 实时更新延迟 < 5 秒
- [ ] 大量日志加载不卡顿（虚拟滚动或分页）

## Out of Scope

以下功能不在本次重构范围内：

- 用户认证和权限系统（保持现有 API_KEY 认证）
- 多语言支持（仅中文）
- 移动端优化（仅支持平板以上设备）
- 实时聊天功能重构（保留现有 `/admin/chat`）
- 后端 API 重构（仅调整前端）
- WebSocket 实时推送（使用 SSE 或轮询）

## Open Questions

所有关键决策已确认：

1. ✅ **技术栈选择**：纯 HTML/CSS/JS（原生技术栈）
   - 原因：简单、易维护、零构建、性能优秀
   - 架构：多 HTML 页面 + 共享 CSS/JS 模块

2. ✅ **图表库选择**：Chart.js
   - 原因：轻量（60KB gzip）、易用、功能够用、社区成熟
   - 支持：折线图、环形图、柱状图等所有需要的图表类型

3. ✅ **实时更新方式**：轮询（Polling）
   - 原因：实现简单、无需后端改动、易于维护
   - 轮询间隔：Dashboard 5s、日志 2s、性能监控 10s、Token 状态 5s
   - 优化：使用 Page Visibility API，只在页面激活时轮询

4. ✅ **实施优先级**：价值优先 + 渐进迁移
   - Phase 1：基础框架 + Dashboard（3-4 天）
   - Phase 2：DeepSeek 渠道管理（2-3 天）
   - Phase 3：GLM 渠道管理（2-3 天）
   - Phase 4：日志 + 性能监控（2-3 天）
   - Phase 5：完善和替换（1 天）
   - 总工作量：12-15 天

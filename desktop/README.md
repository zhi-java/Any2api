# OmniAPI Desktop

> 轻量级桌面客户端 — 将 OmniAPI 核心服务装进托盘，开机即用，无需命令行。

---

## 产品简介

OmniAPI Desktop 是 OmniAPI 的官方桌面应用程序。它将 OmniAPI 核心引擎打包为一个轻量级的 Windows 桌面客户端，通过系统托盘常驻运行，让您无需打开终端、无需记忆命令，即可随时随地使用 API 编排与转换能力。

**核心特点：**

- 🪶 **极致轻量** — 基于 Tauri 构建，利用系统原生 WebView，安装包体积远小于传统 Electron 应用
- 🖥️ **托盘常驻** — 关闭窗口不退出，后台静默运行，随时通过托盘图标调出
- 🚀 **开箱即用** — 安装包内置 Core 运行环境，无需安装 Node.js 或其他依赖
- 🔔 **智能监控** — 实时检测 Core 健康状态，异常崩溃自动恢复并推送系统通知
- 🔒 **本地优先** — 所有服务运行在 `127.0.0.1`，数据不出本机

## 快速上手

### 1. 安装

下载 NSIS 安装包（`.exe`），双击运行，按向导完成安装。安装程序会自动注册开机自启选项和开始菜单快捷方式。

### 2. 首次启动

首次启动会自动打开**初始化向导**，引导您完成以下配置：

1. **渠道选择** — 选择需要对接的 API 渠道
2. **凭据配置** — 填入对应的 API Key / Token
3. **连通性测试** — 自动验证凭据是否有效
4. **端点确认** — 确认 API 请求端点地址

配置完成后，向导会将凭据安全保存在本机 `%AppData%/OmniAPI/` 目录下。

### 3. 日常使用

配置完成后，OmniAPI Desktop 会在系统托盘驻留。您可以通过以下方式使用：

| 操作 | 方法 |
|------|------|
| 打开管理面板 | 双击托盘图标，或在托盘菜单选择「打开面板」 |
| 复制 API 地址 | 托盘菜单 → 「复制 API」 |
| 启动/停止服务 | 托盘菜单 → 「启动」/「停止」 |
| 重启服务 | 托盘菜单 → 「重启」 |
| 退出程序 | 托盘菜单 → 「退出」（会同时停止 Core） |

## 窗口与托盘行为

OmniAPI Desktop 采用**最小打扰**设计哲学：

- **关闭窗口 ≠ 退出程序**：点击窗口关闭按钮，程序会最小化到系统托盘，Core 服务继续运行
- **单实例运行**：重复启动程序不会打开第二个窗口，而是自动激活已有的主窗口
- **开机自启**：可在管理面板首页开启/关闭开机自动启动
- **崩溃自愈**：Core 服务异常退出时，程序会自动尝试重启，并通过 Windows 通知提醒您

## 托盘状态说明

托盘图标通过颜色直观展示当前服务状态：

| 图标颜色 | 状态 | 说明 |
|----------|------|------|
| 🟢 绿色 | 运行中 | Core 服务正常，API 可用 |
| 🟡 黄色 | 需关注 | 服务运行但存在告警 |
| ⚫ 灰色 | 已停止 | Core 服务已手动停止 |
| 🔴 红色 | 已崩溃 | Core 异常退出，正在尝试恢复 |

右键点击托盘图标可打开完整菜单。

## 管理面板

启动服务后，在浏览器访问 `http://127.0.0.1:3000/admin` 即可打开内置的管理面板。您也可以在托盘菜单中点击「打开面板」直接跳转。

管理面板提供以下功能：
- 查看 API 调用统计与日志
- 管理渠道配置与凭据
- 调整服务运行参数
- 开启/关闭开机自启

## 配置文件

所有用户配置保存在 `%AppData%/OmniAPI/desktop.json`：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `port` | `3000` | Core 服务监听端口 |
| `host` | `127.0.0.1` | 监听地址（仅本机） |
| `closeToTray` | `true` | 关闭窗口时隐藏到托盘 |
| `autoStartCore` | `true` | 启动程序时自动启动 Core |
| `launchAtLogin` | `false` | 开机自动启动 |
| `adminApiKey` | `""` | 管理面板 API 密钥 |
| `onboardingCompleted` | `false` | 是否已完成初始化引导 |

## 常见问题

**Q: 程序无法启动，提示缺少 WebView2？**
A: 请从微软官网下载安装 [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/)。

**Q: 修改端口后如何生效？**
A: 在托盘菜单中选择「重启」，Core 将以新端口重新启动。

**Q: 如何彻底卸载？**
A: 通过 Windows「设置 → 应用 → 已安装的应用」找到 OmniAPI Desktop 并卸载。卸载程序会同时清理 Core 二进制文件和开始菜单快捷方式。用户数据目录 `%AppData%/OmniAPI/` 需要手动删除。

**Q: 管理面板打不开？**
A: 请先确认托盘图标为绿色（运行中）状态，再检查防火墙是否阻止了本地 `3000` 端口。

## 凭据获取指南

OmniAPI 对接多个 AI 渠道，不同渠道获取 Token/凭据的方式略有差异。以下是各渠道凭据的详细获取步骤：

---

### DeepSeek（深度求索）

**支持两种模式：Token 模式（推荐） / 账号密码模式**

#### Token 模式 — 从浏览器 Local Storage 获取

1. 用 Chrome/Edge 浏览器访问 [chat.deepseek.com](https://chat.deepseek.com) 并登录
2. 按 `F12` 打开开发者工具，切换到 **Application（应用程序）** 标签
3. 左侧展开 **Local Storage** → 选择 `https://chat.deepseek.com`
4. 在右侧搜索框输入 `userToken`，找到对应的键值
5. 复制 `userToken` 的值（一串长字符串），粘贴到管理面板的 DeepSeek Token 输入框中

> **注意**：`userToken` 会定期过期，失效后需要重新获取。建议多配置几个 Token 以提高可用性。

#### 账号密码模式

1. 在添加凭据时类型选择「账号」
2. 填入 DeepSeek 网页端的登录邮箱和密码
3. 程序会自动模拟登录获取 Token

> **提示**：如遇验证码或风控验证，账号模式可能失败。优先使用 Token 模式。

---

### GLM（智谱清言）

**支持 Token 模式，可选开启访客模式**

#### 从 Cookies 获取 Refresh Token

1. 用浏览器访问 [chatglm.cn](https://chatglm.cn) 并登录
2. 按 `F12` 打开开发者工具，切换到 **Application（应用程序）** 标签
3. 左侧展开 **Cookies** → 选择 `https://chatglm.cn`
4. 在 Cookie 列表中找到名为 `chatglm_refresh_token` 的条目
5. 复制其值，粘贴到管理面板的 GLM Refresh Token 输入框中

> **GLM 的 Token 体系**：访客 Token → Refresh Token → Access Token。程序会自动使用 Refresh Token 换取临时的 Access Token 并缓存，无需手动维护。

#### 访客模式

如果没有配置任何 Token，GLM 渠道会自动启用访客模式（受限使用）。也可以在凭据管理页面手动开启/关闭访客模式。

---

### Qwen（通义千问）

**支持两种模式：Token 模式 / 账号密码模式**

#### Token 模式 — 从 Qwen Studio Cookies 获取

1. 用浏览器访问 [chat.qwen.ai](https://chat.qwen.ai) 并登录
2. 按 `F12` 打开开发者工具，切换到 **Application（应用程序）** 标签
3. 左侧展开 **Cookies** → 选择 `https://chat.qwen.ai`
4. 在 Cookie 列表中找到名为 `token` 的条目
5. 复制其值，粘贴到管理面板的 Qwen Token 输入框中

> **注意**：Qwen 的 `token` 是 JWT 格式，有过期时间。Token 过期后如果配置了账号密码，程序会自动重新登录刷新 Token。

#### 账号密码模式

1. 在添加凭据时类型选择「账号」
2. 填入 Qwen 网页端的登录邮箱和密码
3. 程序会自动调用登录接口获取 JWT Token，Token 过期后也会自动刷新

> **推荐做法**：同时配置 Token 和账号密码，Token 用于日常调用，密码用于 Token 过期后自动续期。

---

### Kimi（月之暗面）

**仅支持 Token 模式**

#### 从浏览器 Local Storage 获取

1. 用浏览器访问 [kimi.com](https://www.kimi.com) 并登录
2. 按 `F12` 打开开发者工具，切换到 **Application（应用程序）** 标签
3. 左侧展开 **Local Storage** → 选择 `https://www.kimi.com`
4. 在右侧搜索框输入 `access_token`，找到对应的键值
5. 复制 `access_token` 的值，粘贴到管理面板的 Kimi Token 输入框中

> **注意**：`access_token` 同样是 JWT 格式，程序会自动检测过期状态。过期后需要重新从浏览器获取。

### 凭据常见问题

**Q: 如何确认凭据有没有配置成功？**
A: 在管理面板的「凭据管理」页面，点击「测试渠道」按钮，会逐一验证所有已配置凭据的有效性，并显示通过/失败的详细结果。

**Q: 为什么 Token 配置后过几天就用不了了？**
A: 上游服务（DeepSeek/GLM/Qwen/Kimi 等）的 Token 都有有效期限制，过期后需要重新获取。建议定期检查凭据状态，或同时配置多个 Token/账号以确保可用性。

**Q: 可以同时配置多个 Token 吗？**
A: 可以。在凭据管理页面可以添加多个 Token，程序会自动在有效 Token 之间轮询调度，提高并发能力和可用性。
